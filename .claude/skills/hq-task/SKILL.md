# توزيع مهمة على الفريق

أنت المدير التنفيذي. المهمة: **$ARGUMENTS**

## 1. افهم وقسّم
- اقرأ `hq/roster.json` حتى تعرف الفريق ومن متاح.
- إذا الطلب غامض لدرجة تغيّر النتيجة، اسأل المستخدم سؤال واحد. غير هذا ابدي.
- قسّم المهمة لمهام صغيرة، كل وحدة لموظف واحد مسؤول عنها (شوف وصف كل موظف بـ `.claude/agents/`).

## 2. سجّل البداية
لكل موظف:
```bash
node hq/hq.mjs start <id> "<مهمته بجملة قصيرة>"
```

## 3. وزّع الشغل
- استخدم أداة Agent مع `subagent_type` = معرّف الموظف (مثل `db-engineer`).
- المهام المستقلة أرسلها **بنفس الرسالة** حتى تشتغل بالتوازي. المعتمدة على بعض (مثلاً migration ثم endpoint ثم صفحة) بالترتيب.
- بكل تكليف اكتب: الهدف، الملفات المعنية، معيار القبول، وشنو خارج النطاق.

## 4. المراجعة (إلزامية لأي تعديل كود)
```bash
node hq/hq.mjs review <id>
```
- `code-reviewer` يراجع الـ diff.
- `security-auditor` إذا التعديل يمس المصادقة أو الصلاحيات أو الروابط العامة أو الصور.
- `qa-tester` يشغّل `release-check`.
- إذا طلعت ملاحظات حقيقية، رجّعها لنفس الموظف يصلّحها.

## 5. سجّل الإنجاز والـ XP
```bash
node hq/hq.mjs done <id> <xp> "<شنو انجز>"
```
| حجم المهمة | XP |
|---|---|
| صغيرة | 10 |
| متوسطة | 25 |
| كبيرة | 50 |
| + نجحت المراجعة من أول مرة | +10 |
| + معها اختبارات | +10 |
| المراجِع اللي لگى خطأ حقيقي | 15 لكل خطأ |

المدير (`ceo`) ياخذ 5 XP لكل مهمة كاملة يغلقها.

## 6. سلّم
- commit بوصف واضح على البرانچ الحالي (لا تسوي push إلا إذا المستخدم طلب أو إعدادات الجلسة تطلب).
- رد على المستخدم بالعربي: شنو انسوى، منو سواه، نتيجة الفحص، وأي شي يحتاج قراره.
