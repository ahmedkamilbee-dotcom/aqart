# عقاراتي

منصة عربية لإدارة عمل الوكلاء والمكاتب العقارية: العقارات، العملاء، مواعيد المتابعة، الاشتراكات، ومشاركة عروض العقارات بروابط عامة.

## الموجود في المشروع

- لوحة وكيل عربية تدعم الهاتف والكمبيوتر، مع تسجيل دخول وصلاحيات منفصلة للوكيل والمدير.
- إدارة العقارات مع بحث وتصفية وصفحات نتائج، حتى ما تنحصر القائمة بأول مجموعة عقارات.
- خريطة تفاعلية لمحافظات العراق الـ19، لاختيار المحافظة عند تسجيل العقار وفلترة النتائج؛ وتعمل أيضاً من القائمة ولوحة المفاتيح.
- سجل عملاء ومراحل تواصل ومواعيد أسبوعية وملخص أداء.
- صفحة عامة لكل عقار يُنشأ له رابط مشاركة. بيانات المالك لا تظهر، ورقم الوكيل لا يظهر إلا بموافقته. يمكن إيقاف الرابط.
- اشتراكات تجريبية ومدفوعة؛ التفعيل والتجديد حالياً يدويان عبر واتساب ولوحة المدير.
- واجهة تسويقية على الصفحة الرئيسية تشرح المنتج والباقات.

## بيانات خريطة المحافظات

تستخدم الخريطة حدود 17 محافظة من مجموعة geoBoundaries المبسطة (CC0، نسخة 2022)، وحدود محافظتي حلبجة والسليمانية من OpenStreetMap حتى تظهر المحافظة المستحدثة وحدّها مع السليمانية. بيانات OpenStreetMap مرخصة وفق ODbL 1.0، مع نسبها لمساهمي OpenStreetMap داخل الواجهة. تُستخدم الخريطة للتوضيح وتحديد موقع العقار فقط، وليست مرجعاً قانونياً أو مساحياً.

- geoBoundaries: [بيانات العراق ADM1](https://github.com/wmgeolab/geoBoundaries/blob/9469f09/releaseData/gbOpen/IRQ/ADM1/geoBoundaries-IRQ-ADM1_simplified.geojson).
- OpenStreetMap: [حد حلبجة](https://www.openstreetmap.org/relation/3826029)، [حد السليمانية](https://www.openstreetmap.org/relation/2969790)، و[شروط بيانات ODbL](https://www.openstreetmap.org/copyright).

## التشغيل المحلي

المتطلبات: Python 3.11 أو أحدث، وNode.js حديث، وYarn 1.

### 1. قاعدة البيانات والتخزين

1. أنشئ مشروع Supabase.
2. شغّل ملفات `supabase/migrations/` بالترتيب:
   - `20261024000000_init_schema.sql`
   - `20261027000000_leads_crm.sql`
   - `20261027000100_crm_analytics.sql`
   - `20261027000200_public_property_sharing.sql`
   - `20261027000300_storage_provider.sql`

   إذا كانت أول أربعة ملفات مطبّقة عندك، شغّل الملف الخامس فقط.
3. أنشئ من Supabase Storage حاوية خاصة اسمها `property-images`.
4. انسخ رابط قاعدة البيانات من Transaction Pooler، المنفذ 6543. انسخ كذلك عنوان مشروع Supabase ومفتاح `service_role` من إعدادات المشروع؛ المفتاح الأخير يبقى في الخادم ولا يوضع بملفات الواجهة. إذا عندك صور قديمة في Emergent ولم تنسخها بعد، احتفظ مؤقتاً بـ`EMERGENT_LLM_KEY` أيضاً حتى تبقى قابلة للعرض.

### 2. الخادم

```powershell
cd backend
Copy-Item .env.example .env
# عدّل إعدادات قاعدة البيانات والتخزين ونطاقات المشاركة قبل التشغيل
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python server.py
```

الخادم المحلي يعمل عادة على `http://localhost:8000`.

### 3. الواجهة

```powershell
cd frontend
Copy-Item .env.example .env
# أضف رقم واتساب وروابط التواصل الخاصة بكم
corepack yarn install
corepack yarn start
```

الواجهة المحلية تعمل عادة على `http://localhost:3000`. رابط المشاركة يمرّ بالخادم ليعرض بطاقة معاينة غنية في تطبيقات المحادثة، ثم يحوّل الزبون إلى صفحة الواجهة. عند النشر اضبط `PUBLIC_API_URL` و`REACT_APP_BACKEND_URL` على نطاق الخادم، و`PUBLIC_APP_URL` على نطاق الواجهة، واجعل الواجهة تعيد المسار `/share/...` إلى `index.html`.

## نشره للناس

- اضبط `ENV=production`، ومفتاح `JWT_SECRET` فريداً بطول 32 بايت على الأقل، وكلمة مرور مدير قوية، و`CORS_ORIGINS` على نطاقات HTTPS الفعلية، و`PUBLIC_APP_URL` و`PUBLIC_API_URL` على النطاقين العامين عبر HTTPS، و`TRUSTED_HOSTS` على أسماء نطاق الخادم فقط دون `https://`.
- اضبط `DB_SSL_CA` بشهادة Supabase حتى يتحقق الخادم من شهادة قاعدة البيانات.
- وثائق API التفاعلية تُغلق تلقائياً في الإنتاج. إعدادات تحديد المحاولات داخل الذاكرة تحمي نسخة خادم واحدة؛ عند تشغيل عدة نسخ، أضف تحديداً مشتركاً للمحاولات في Redis أو على بوابة الاستضافة.
- استخدم حاوية تخزين خاصة، واحفظ `SUPABASE_SERVICE_ROLE_KEY` في أسرار بيئة الخادم فقط.
- أضف قنوات التواصل الخاصة بكم في `frontend/.env` قبل فتح التسجيل؛ من دون رقم واتساب لن تظهر للزبائن طريقة طلب تفعيل الباقات المدفوعة.
- جهّز نسخة احتياطية لقاعدة البيانات والصور، وسياسة خصوصية وشروط استخدام قبل استقبال بيانات مكاتب حقيقية.
- الدفع الإلكتروني غير مدمج حالياً؛ الباقات المدفوعة تُفعّل يدوياً بعد التواصل مع الإدارة.

## الفحوصات

لتثبيت أدوات الفحص:

```powershell
cd backend
python -m pip install -r requirements-dev.txt
python -m pytest
```

اختبارات `backend/tests` اختبارات تكامل؛ شغّلها من مجلد `backend` وتحتاج قاعدة بيانات وخادماً شغالين وإعداد حساب المدير التجريبي. لتجهيز الواجهة للإنتاج:

```powershell
cd frontend
corepack yarn build
```

## الملفات الرئيسية

- `backend/server.py`: الحسابات، العقارات، الاشتراكات، التخزين، وإعدادات الأمان.
- `backend/leads.py`: سجل العملاء والتحليلات.
- `frontend/src/pages/LandingPage.js`: الصفحة التسويقية.
- `frontend/src/pages/PublicPropertyPage.js`: صفحة العقار التي يفتحها الزبون من رابط المشاركة.
- `supabase/migrations/`: مخطط قاعدة البيانات وترقياته.

## الأمان والخصوصية

- لا ترفع ملفات `.env` إلى Git أو ترسل مفتاح الخدمة الموجود فيها.
- كل وكيل يرى عقاراته وسجلات عملائه فقط؛ المدير العام يستطيع مراجعة بيانات النظام.
- الصفحة العامة للعقار لا تعرض اسم المالك أو رقم هاتفه. عرض رقم الوكيل اختيار اختياري من نافذة مشاركة العقار.
- الصور تبقى في حاوية خاصة، ويقدّمها الخادم بعد التحقق من ملكية الملف أو من رابط مشاركة ساري.
- الوكيل يقدر يوقف رابط المشاركة حتى بعد انتهاء اشتراكه.
